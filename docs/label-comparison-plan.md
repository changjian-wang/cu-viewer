# Fields 标签对照实施方案

日期：2026-11-13

状态：阶段性实现，仅修改 `cu-viewer`，按用户要求提交并推送以便继续。范围更正与自动化检查已通过，但设计图逐项 UX 验收及真实同文档对照 Demo 尚未完成；不视为需求已验收，不发布。

## 1. 目标与范围

在现有 **Fields** 中集中查看标签值、提取值和匹配状态，让用户快速发现不一致、误提取和漏提取。移除独立 **Label** tab，不覆盖标签或分析结果，不增加标签编辑、自动纠错或重新分析。

本轮只修改 `cu-viewer`：比较模型、Fields、来源预览、Demo、组件页面及测试。需求中的 azd 命令是集成背景，不属于本轮 CLI 改动范围；此前对 Go 扩展源码、测试、文档及内嵌资源的修改已全部撤销，相关工作区恢复干净。

保留现有 Figures、JSON 全文查看、Markdown Worker、PDF 翻页与原文不闪屏等改动；本需求不顺带重构其他结果页。

## 2. 需求基线与方案约定

三态颜色、精确匹配、数组按下标配对、叶子值计数和无效结果告警降级已经确认。下文对空容器、类型冲突、界面占位等边界给出具体实现约定，与本方案一起审阅，不代表这些细节此前均已单独确认。

### 2.1 自动加载与展示模式

配套文件命名为：

```text name="配套文件命名"
invoice.pdf
invoice.pdf.labels.json
invoice.pdf.result.json
```

Demo 根据项目内样本声明加载配套资源；组件只使用明确传入的数据，不自行访问本地相邻文件，也不要求外部宿主新增选项。真实结果文件统一为 `<源文件完整文件名>.result.json`。新增 PDF + Labels 入口直接加载现成 `labels/invoice.pdf` 和 `labels/invoice.pdf.labels.json`；没有真实配套结果时只显示标签参考模式。

| 输入情况 | Fields 展示 | 比对与颜色 |
|---|---|---|
| 仅有效分析结果，没有标签 | 保留现有提取值查看及可选 Confidence 列 | 默认背景；不显示正确／错误统计 |
| 有标签，没有结果或首个 content 未声明 `fields` | `Field Name / Label Value` | 两列参考模式，不把全部标签误判为漏提取 |
| 有标签，且首个 content 声明有效 `fields` | `Field Name / Label Value / Extracted Value` | 启用比对、统计和状态筛选 |
| 有标签，且 `fields: {}` | 三列 | 有标签值的字段判为漏提取 |
| 有标签，结果文件损坏、不可读或格式不支持 | 明确告警，继续两列标签视图 | 不生成比对结论 |

必须区分“没有 `fields`”和“存在空 `fields`”，不能仅用解析后的字段数量判断可比性。`fields: null` 或数组等错误形状属于无效结果，不按空对象处理。

完整响应使用 `result.contents[0].fields`；裸结果沿用现有解析器支持的 `contents[0].fields`。首版只关联第一个 content，不根据名称、值或来源位置猜测其他 content 的标签对应关系。保留现有 content 切换；其他 content 不套用第一份标签，并明确提示未关联标签。

### 2.2 精确匹配

- 按完整语义字段路径配对，数组路径包含原始行下标；不依靠显示名称、来源 ID 或坐标猜测对应关系。
- 比较字段类型、值是否存在及相应 `value*` 内容，不做类型转换、日期归一化或数值容差处理。
- 字符串大小写、首尾空白、内部空白和换行差异均判为不匹配。
- 数值按已解析的数值精确比较，同一数值类型中的 `1` 和 `1.0` 相等。
- `0`、`false`、空字符串和显式 `null` 都是值，不能按“未返回”处理。
- 对象按子字段比较，不受 JSON 属性排列顺序影响；数组严格按下标和子字段路径比较，不自动重排或按业务键配对。
- `confidence`、`source`、`spans`、`kind` 和其他非值元数据不参与值相等判断。

| 标签值 | 提取值 | 内部判定 | 背景状态 |
|---|---|---|---|
| 存在 | 存在且相同 | 匹配 | 正常 |
| 存在 | 存在但不同 | 值不一致 | 错误 |
| 不存在 | 存在 | 误提取 | 错误 |
| 存在 | 不存在 | 漏提取 | 错误 |
| 两侧均未提供值 | 两侧均未提供值 | 不参与值比对 | 默认，不计入正确／错误 |

内部保留错误原因，供文字提示、无障碍说明和测试使用；不通过新增背景色区分错误种类。

### 2.3 三态颜色与低置信度

仅使用三类状态背景：

| 状态 | 颜色语义 |
|---|---|
| 默认／未比较 | 设计图中的淡蓝色 |
| 匹配 | 设计图中的绿色 |
| 错误 | 设计图中的红色 |

颜色名称不代表纯色值。实现时对照提供的设计原图取色，集中为三枚颜色 token，由 Fields、来源填色、flyout 状态区和 Legend 共用。不额外增加橙色、深红或数组专属的第四种状态背景。

低置信度独立使用更深、带透明度的红色描边：

- 只读取提取值自身的 confidence；标签 confidence 不参与此规则。
- 沿用当前可配置阈值及严格 `< threshold` 判定。
- 绿色匹配背景可以同时具有低置信度红框。
- 没有 confidence 不伪造分数，也不因此将值标为错误。

### 2.4 统计与数组筛选

- 正确／错误数按叶子值统计，数组单元格分别计数，对象和数组容器不重复计数。
- 已提供的空对象／空数组没有后代值时作为终端值处理；双方均无值不计入正确／错误数。
- 类型不兼容时，冲突节点作为一个终端错误，不再把其后代重复计入；两侧原始内容仍可检查。
- 数组全部匹配才进入正确筛选；至少一个错误单元格就进入错误筛选。
- 筛选数组时保留完整上下双表，不能只留下一个错误单元格而丢失上下文。

计数单位是值，不是表数。一个数组有 11 个匹配单元格、1 个错误单元格时，贡献正确 11、错误 1，但整张表归入错误筛选。

## 3. 数据与组件设计

### 3.1 独立、只读的比较模型

在现有解析模型之上新增内部比较层，不把标签写入 `result`，也不把两套 `CuField` 的来源混成一份。

每个比较节点保存：

- 规范化语义路径、名称及子节点。
- 原始标签字段引用和原始提取字段引用，任一侧可以缺失。
- 匹配状态、错误原因和叶子统计。
- 两侧各自的来源身份，供选择、悬停、定位和复制使用。

复用现有字段路径、类型解析和数组投影能力。对象值必须按解析后的子字段比较，不能直接比较包含 `source`、confidence 等元数据的原始对象记录。

同名字段按完整路径区分；字段名中的 `/`、`~` 沿用 JSON Pointer 转义。行集合使用两侧字段的并集，标签顺序为默认顺序，额外提取字段附在相应层级末尾，不能隐藏误提取。

比较遍历使用显式栈，避免深层对象递归溢出；以输入版本缓存，不能在鼠标移动、缩放或每次单元格绘制时重新比较全文。比较不依赖 PDF 渲染完成或来源坐标可用。

### 3.2 统一 Fields，而不是复制一套 Viewer

扩展现有 Fields 的内部查看模式：

1. 提取值模式。
2. 标签参考模式。
3. 标签／提取值对照模式。

继续复用折叠、字段操作、数组投影、搜索、循环导航和定位。仅在需要时提取共享的单元格或双表组件，不复制第二套 Viewer、SourcePane 或完整 Fields 实现。

保留公开的 `source`、`result`、`labels` 组件输入。移除 Label tab 及其内部选择分支，但不删除 Markdown、Paragraphs、Figures、Signatures、Info、Result 等现有入口。

对照模式固定三列，不把已有“显示 Confidence 列”设置误当成对照三列。置信度通过 flyout 和描边展示；参考模式固定两列。切换模式不覆盖用户保存的提取值列设置。

### 3.3 双表与缺失占位

数组上表显示 Label Value，下表显示 Extracted Value，采用相同的列投影并按原始索引对应。

- 提取表单元格使用三态颜色，标签值不因匹配而重复填绿。
- 标明两侧真实的返回条数。
- 缺少行或单元格时，比较视图使用明确的“无标签／未提取”占位，不伪造值、行来源或 confidence。
- 漏提取的 Extracted Value 占位在 Fields 标红，保留标签真实值与点击定位能力。
- 展开对象、过滤、来源定位和切换结果页后保持合理的阅读位置。

长数组必须有界挂载，可复用现有虚拟化依赖。搜索和比较基于完整数据，不能仅处理当前挂载行；导航到未挂载的首尾行时先滚动到索引，再揭示和聚焦目标。

### 3.4 搜索、底栏与筛选

- 搜索覆盖字段名、标签值和提取值，保留现有搜索输入行为；不把搜索的大小写处理方式混入精确比较。
- 底栏增加绿色正确数按钮、红色错误数按钮；按钮互斥，再次点击当前按钮恢复全部。
- 本方案采用当前比较内容的全量正确／错误统计，不随搜索或状态筛选改变，避免切换筛选时另一按钮计数归零；tooltip 明确“值数”口径。
- 字段导航只在当前搜索和状态筛选目标中循环；显示出来的上下文值不冒充匹配目标。
- 保持 44px 底栏和紧凑图标／数字，在现有窄宽布局中不横向溢出。
- 用文字、图标和无障碍名称区分状态，不能仅依靠颜色。

## 4. 来源预览与交互

### 4.1 两侧来源保持独立

- 点击 Label Value 定位标签自己的来源；点击 Extracted Value 定位分析结果自己的来源。
- 原始多边形、多片段、页号和实际 PDF 几何保持不变。
- 没有提取来源时不能借用标签框冒充提取来源；无来源时明确提示。
- 默认比较高亮使用提取来源，不同时叠加两套重复填色框；标签侧选择使用现有临时／固定定位机制。
- 漏提取不在预览常驻错误色块；仍可点击标签定位其来源，但不因此创建虚假的提取框。

两侧动作始终持有原字段和侧别，避免同一路径的标签与提取值抢占悬停、选择、复制或导航目标。

### 4.2 Flyout 与 Legend

有标签时 flyout 上方显示标签值，下方显示提取值，并保留提取 confidence；没有一侧值时明确显示状态。状态区使用统一三态颜色。

Legend 同步说明默认、匹配、错误三态及独立的低置信度描边，不再把参考绿色或高置信度绿色误称为“匹配成功”。

颜色逻辑只应用于 Fields 的字段对照上下文，不借修改共享 helper 改变 Paragraphs、Figures、Signatures 等无关视图。

切换 tab、筛选或更改阈值不能重载 Source、重置 PDF 页码／缩放／旋转，或重放旧的定位请求。更换输入时清除旧比较与旧来源请求。

## 5. Viewer、Demo 与宿主边界

- 比较与展示只在 Viewer 中完成；文件路径发现、CLI 命令和外部资源更新不在本轮范围。
- Demo 从项目资源加载 PDF、Receipt PNG、Large PDF、PDF + Labels 四个入口，不依赖 Downloads、用户机器路径或新增服务接口。
- 既有三个真实分析结果只改名为 `.pdf.result.json`／`.png.result.json`，不重写 JSON，不调用 Analyze。
- 只有标签时不伪造分析结果；非法或不支持的已提供结果在页面明确告警，继续标签参考模式，不显示“全部匹配”。
- 保留公开 `source`、`labels`、`result` 输入及既有页面安全校验。独立页面可以显示宿主主动提供的警告，但不要求修改宿主。
- 标签查看／对照操作不能自动启用 analyzer 字段排序写回。

## 7. 实施顺序与完成条件

| 阶段 | 工作 | 完成条件 |

| A | 比较模型及单测 | 四种有值组合、精确比较、对象、数组与计数均可独立验证 |

## 8. 验收与验证

### 8.1 功能矩阵

必须覆盖：

1. 仅标签、仅结果、双文件、结果缺失、无 `fields`、空 `fields`、无效结果和无效标签。
2. 相同值、不同值、误提取、漏提取、两侧均未提供值，以及 `0`、`false`、空字符串、`null`。
3. 大小写／空白／换行差异、不同类型、对象键顺序、同名嵌套字段及特殊字段名。
4. 数组相同、换序、长短不一、缺行／缺列、空数组、混合正确／错误单元格；容器不重复计数。
5. 双值 flyout、两侧位置不同、跨页、无来源、低 confidence 与绿色背景同时存在。
6. 搜索三个维度、正确／错误筛选、循环导航、键盘访问及被筛选隐藏的固定选择。
7. 多 content 不串用标签，换数据不保留旧比对，标签会话不写 analyzer 偏好。
8. 原始文件与字段不被修改，点击定位不触发重新分析或外部请求。

### 8.2 大文档与视觉

- 在 Chrome、Edge 验证，覆盖现有 1030／1440 宽度、小缩放、旋转及 DPR 2 来源框。
- 颜色从设计图对齐，文字对背景满足 AA 对比度；不通过放宽旧截图容差掩盖视觉变化。
- 覆盖至少 1,000 行、10 列的双表：完整搜索、首尾定位与统计正确，挂载 DOM 不随全部行数线性增长。
- 保持现有生产性能门限：冷切换 1,000 ms、热切换 350 ms、长任务 100 ms、主线程 heap 增长 64 MiB；另外实际测量打开／筛选比较页，不能仅依赖旧切 tab 测试。
- 复用现有 41 页 Large PDF／保存结果做大文档回归，不重新 Analyze 或覆盖真实结果。

现有标签示例目录只有配对 PDF 和 labels。可先完成明确标记的自动化测试构造；真实标签对照验收需补同一份 PDF 的真实结果和人工预期，不能将其他 PDF 的结果凑成配对或伪造 Demo 分析结果。若真实配对数据尚未提供，必须把该验收项标为未验证，不能宣称已经完成。
