# Fields 标签对照实施方案

日期：2026-11-13；最新需求更新：2026-11-19。

状态：2026-11-19 的反馈第 11 项更新了第 16 节的纯文字决定：PDF 浮层中仅实际返回的提取值复用 Fields 底色，标签值、缺失占位和低置信度徽标保持原样，不把红框搬进浮层。默认并排和至少一处错误即纳入数组错误筛选不变。继续复用真实 invoice 结果，不增加 Azure 分析调用。

2026-11-16 此前修复边界：无标签模式以 `f452476` 为兼容性基线，标签对照不改变其配色、Confidence、单表、浮层和 Legend。随后修复可读名称搜索、两侧数组摘要预览及仅对照模式的默认布局；Go 侧只同步完整生产资源并重建本机扩展，不新增业务逻辑。之后用户明确要求无标签 PDF 的配色与风格和标签模式匹配，本轮按第 14 节统一其视觉，不改变单表、Confidence、布局偏好或数据语义；图片和非 Fields 详情仍保留此前边界。

## 1. 目标与范围

在现有 **Fields** 中集中查看标签值、提取值和匹配状态，让用户快速发现不一致、误提取和漏提取。移除独立 **Label** tab，不覆盖标签或分析结果，不增加标签编辑、自动纠错或重新分析。

本轮包含前端比较模型、Fields、来源预览、Demo、页面和测试，以及 Go 宿主的 `label show` 同名文件发现、可选结果会话、帮助、文档和完整内嵌资源。早期“只改 cu-viewer”的范围已被本次明确确认取代。浏览器不获得任意本地文件发现权限，不增加结果加载选项。

保留现有 Figures、JSON 全文查看、Markdown Worker、PDF 翻页与原文不闪屏等改动；本需求不顺带重构其他结果页。

## 2. 需求基线与方案约定

本次确认五态背景、状态色标题／尖角、精确匹配、数组按下标配对、叶子值计数及无效结果告警降级。正文中的“label tab”统一指既有 Fields，`.resultjson` 统一为 `.result.json`，完整响应字段路径为 `result.contents[0].fields`。此前三态配色及常驻紫色字段标题不再作为当前验收基线。

### 2.1 自动加载与展示模式

配套文件命名为：

```text name="配套文件命名"
invoice.pdf
invoice.pdf.labels.json
invoice.pdf.result.json
```

Demo 根据项目内样本声明加载配套资源；组件只使用明确传入的数据，不自行访问本地相邻文件，也不要求外部宿主新增选项。真实结果文件统一为 `<源文件完整文件名>.result.json`。PDF + Labels 入口加载现成 PDF／labels 及本轮真实分析保存的 `labels/invoice.pdf.result.json`，直接进入完整三列对照；手工仅加载标签时仍保留参考模式。

| 输入情况 | Fields 展示 | 比对与颜色 |
|---|---|---|
| 仅有效分析结果，没有标签 | 保留现有提取值查看及可选 Confidence 列 | 原有置信度填色、浮层和 Legend；不显示正确／错误统计 |
| 有标签，没有结果或首个 content 未声明 `fields` | `Field Name / Label Value` | 两列参考模式，不把全部标签误判为漏提取 |
| 有标签，且首个 content 声明有效 `fields` | `Field Name / Label Value / Extracted Value` | 启用比对、统计和状态筛选 |
| 有标签，且 `fields: {}` | 三列 | 有标签值的字段判为漏提取 |
| 有标签，结果文件损坏、不可读或格式不支持 | 明确告警，继续两列标签视图 | 不生成比对结论 |

必须区分“没有 `fields`”和“存在空 `fields`”，不能仅用解析后的字段数量判断可比性。`fields: null` 或数组等错误形状属于无效结果，不按空对象处理。

完整响应使用 `result.contents[0].fields`；裸结果沿用现有解析器支持的 `contents[0].fields`。首版只关联第一个 content，不根据名称、值或来源位置猜测其他 content 的标签对应关系。保留现有 content 切换；其他 content 不套用第一份标签，并明确提示未关联标签。

### 2.2 精确匹配

- 按完整语义字段路径配对，数组路径包含原始行下标；不依靠显示名称、来源 ID 或坐标猜测对应关系。
- 比较字段类型、值是否存在及相应 `value*` 内容，不做类型转换、日期归一化或数值容差处理。
- 字符串大小写、首尾空白、内部空白和换行差异均判为不匹配。
- 数值按已解析的数值精确比较，同一数值类型中的 `1` 和 `1.0` 相等。
- `0`、`false`、空字符串和显式 `null` 都是值，不能按“未返回”处理。
- 对象按子字段比较，不受 JSON 属性排列顺序影响；数组严格按下标和子字段路径比较，不自动重排或按业务键配对。
- `confidence`、`source`、`spans`、`kind` 和其他非值元数据不参与值相等判断。

| 标签值 | 提取值 | 内部判定 | 背景状态 |
|---|---|---|---|
| 存在 | 存在且相同 | 匹配 | 正常 |
| 存在 | 存在但不同 | 值不一致 | 错误 |
| 不存在 | 存在 | 误提取 | 错误 |
| 存在 | 不存在 | 漏提取 | 错误 |
| 两侧均未提供值 | 两侧均未提供值 | 不参与值比对 | 中性透明，不计入正确／错误 |

内部保留错误原因，供文字提示、无障碍说明和测试使用；不一致和误提取共用浅红，漏提取按已确认图例使用深红。

### 2.3 五态颜色与低置信度

PDF 的 Fields 和来源使用同一组背景，浮层正文不着色。按 2026-11-18 补充需求，无 labels PDF 的普通／对象／数组默认统一使用 `#DCFBD7` 绿底，来源和图例同步，仅覆盖展示层，不标记匹配、不改变置信度红框或缺失占位。下表继续描述有 labels 输入时的原配色；标签参考／对照及其未绑定 content、图片和其他视图不受这次覆盖影响：

| 状态 | 颜色语义 |
|---|---|
| 未比较普通／对象值 | 旧淡蓝 `#ECF3FC` |
| 未比较数组值 | 旧数组蓝 `#DEE9FA` |
| 匹配 | 旧绿色 `#DCFBD7` |
| 不一致／误提取 | 旧浅红 `#FFDADD` |
| 可比较时仅有标签、无提取值 | 旧深红 `#F8C0C8` |

按 2026-11-17 用户确认，颜色集中恢复为 MUI 切换前的共享 token；PDF Fields 的 hover／固定轮廓为旧紫色 `#8063B5`／`#5B21B6`，保留紫框至少 3:1、正文至少 4.5:1 的检查。双方都无值的占位保持透明，不作为第六种匹配色。没有可比较结果时不把标签参考视图误标为漏提取。

低置信度独立使用更深、带透明度的红色描边：

- 仅在提取值确实存在时读取自身 confidence；标签或父级 confidence 不参与此规则，0、false、空字符串及显式 null 不按缺失处理。
- 沿用当前可配置阈值及严格 `< threshold` 判定。
- 绿色匹配背景可以同时具有低置信度红框。
- 没有 confidence 不伪造分数，也不因此将值标为错误。
- 红框完整恢复旧值 `#B43C4B99`、60% 不透明度。用户已确认该较淡描边，不再声称达到 3:1；不通过提高不透明度改写旧色。Legend 用示例值和红框演示叠加关系，无 labels PDF 使用默认绿底、有比较时可演示匹配绿底，两者不混淆状态含义。已返回的分数独立显示，不因开关描边而隐藏或改写。
- 紫色交互框在低置信度来源装饰之外留出 3 CSS px，包含抗锯齿空间；键盘焦点移到值内红框之外。只改装饰，不修改真实来源或点击命中。

### 2.4 统计与数组筛选

- 正确／错误数按叶子值统计，数组单元格分别计数，对象和数组容器不重复计数。
- 已提供的空对象／空数组没有后代值时作为终端值处理；双方均无值不计入正确／错误数。
- 类型不兼容时，冲突节点作为一个终端错误，不再把其后代重复计入；两侧原始内容仍可检查。
- 数组全部匹配才进入正确筛选；至少一个错误单元格就进入错误筛选。
- 筛选数组时保留完整上下双表，不能只留下一个错误单元格而丢失上下文。

计数单位是值，不是表数。一个数组有 11 个匹配单元格、1 个错误单元格时，贡献正确 11、错误 1，但整张表归入错误筛选。

## 3. 数据与组件设计

### 3.1 独立、只读的比较模型

在现有解析模型之上新增内部比较层，不把标签写入 `result`，也不把两套 `CuField` 的来源混成一份。

每个比较节点保存：

- 规范化语义路径、名称及子节点。
- 原始标签字段引用和原始提取字段引用，任一侧可以缺失。
- 匹配状态、错误原因和叶子统计。
- 两侧各自的来源身份，供选择、悬停、定位和复制使用。

复用现有字段路径、类型解析和数组投影能力。对象值必须按解析后的子字段比较，不能直接比较包含 `source`、confidence 等元数据的原始对象记录。

同名字段按完整路径区分；字段名中的 `/`、`~` 沿用 JSON Pointer 转义。行集合使用两侧字段的并集，标签顺序为默认顺序，额外提取字段附在相应层级末尾，不能隐藏误提取。

比较遍历使用显式栈，避免深层对象递归溢出；以输入版本缓存，不能在鼠标移动、缩放或每次单元格绘制时重新比较全文。比较不依赖 PDF 渲染完成或来源坐标可用。

### 3.2 统一 Fields，而不是复制一套 Viewer

扩展现有 Fields 的内部查看模式：

1. 提取值模式。
2. 标签参考模式。
3. 标签／提取值对照模式。

继续复用折叠、字段操作、数组投影、搜索、循环导航和定位。仅在需要时提取共享的单元格或双表组件，不复制第二套 Viewer、SourcePane 或完整 Fields 实现。

保留公开的 `source`、`result`、`labels` 组件输入。移除 Label tab 及其内部选择分支，但不删除 Markdown、Paragraphs、Figures、Signatures、Info、Result 等现有入口。

对照模式固定三列，不把已有“显示 Confidence 列”设置误当成对照三列。置信度通过 flyout 和描边展示；参考模式固定两列。切换模式不覆盖用户保存的提取值列设置。

没有保存布局时，三列对照默认分栏为约 45% Source／55% 结果；普通和参考模式保留原默认比例。已有设置优先，切换模式及刷新不改写记录，双击分隔条复位到当前模式默认值。数组继续共享列宽与横向滚动，窄屏不删列、不改字段顺序。

### 3.3 双表与缺失占位

数组默认左侧显示 Label Value，右侧显示 Extracted Value，采用相同的列投影并按原始索引对应。每组的 `Stacked`／`Side by side` 可临时切换为上下／并排，刷新或更换输入后默认并排；不改 Source 分栏、数据或用户配置，仅可比较的双表显示切换按钮。参考模式和无标签数组不变。

两种布局均共享水平滚动位置，任意一侧横向滚动都同步另一侧；标签切换和折叠恢复后仍对齐。上下布局的手动纵向滚动独立，并排布局则同步纵向滚动以对齐同行，不影响其他数组表。切换布局时保留并限制滚动位置；并排初次对齐采用标签表的当前行。滚动按两表共同可滚动范围限制，避免反馈循环或末端列错位。

左上角的 `#` 表头同时固定在顶部和左侧，使用不透明背景和高于其他表头及行号的层级，避免横向或纵向滚动时被覆盖。

- 提取表单元格使用五态颜色，标签值不因匹配而重复填绿。
- 标明两侧真实的返回条数。
- 缺少行或单元格时，比较视图使用明确的“无标签／未提取”占位，不伪造值、行来源或 confidence。
- 漏提取的 Extracted Value 占位在 Fields 使用深红；整个对象或数组缺失时，容器也正确标为标签-only，计数仍只累计终端值。
- 展开对象、过滤、来源定位和切换结果页后保持合理的阅读位置。

长数组必须有界挂载，可复用现有虚拟化依赖。搜索和比较基于完整数据，不能仅处理当前挂载行；导航到未挂载的首尾行时先滚动到索引，再揭示和聚焦目标。

### 3.4 搜索、底栏与筛选

- 搜索覆盖字段名、标签值和提取值，保留现有搜索输入行为；不把搜索的大小写处理方式混入精确比较。
- 底栏增加绿色正确数按钮、红色错误数按钮；按钮互斥，再次点击当前按钮恢复全部。
- 本方案采用当前比较内容的全量正确／错误统计，不随搜索或状态筛选改变，避免切换筛选时另一按钮计数归零；tooltip 明确“值数”口径。
- 字段导航只在当前搜索和状态筛选目标中循环；显示出来的上下文值不冒充匹配目标。
- 保持 44px 底栏和紧凑图标／数字，在现有窄宽布局中不横向溢出。
- 用文字、图标和无障碍名称区分状态，不能仅依靠颜色。

## 4. 来源预览与交互

### 4.1 两侧来源保持独立

- 点击 Label Value 定位标签自己的来源；点击 Extracted Value 定位分析结果自己的来源。
- 原始多边形、多片段、页号和实际 PDF 几何保持不变。
- 没有提取来源时不能借用标签框冒充提取来源；无来源时明确提示。
- 默认比较高亮使用提取来源，不同时叠加两套重复填色框；标签侧选择使用现有临时／固定定位机制。
- 漏提取使用标签自己的真实来源绘制深红，不伪造提取框。标签页尺寸独立于分析结果，英寸标签与像素提取值可以同时显示，悬停一侧不改变另一侧固定框。
- 标签片段安全合框时，按比较节点识别同一字段，另一侧提取区域不作为不同字段阻挡；仍只合并标签自己的来源，不借用提取坐标。真正不同字段的阻挡保护不变，适用于标量、对象内叶子值和数组单元格，不强行合并整组选中。

两侧动作始终持有原字段和侧别，避免同一路径的标签与提取值抢占悬停、选择、复制或导航目标。

### 4.2 Flyout 与 Legend

有标签时 flyout 上方显示标签值，下方显示提取值，并保留提取 confidence；没有一侧值时明确显示状态。PDF 浮层标题条和尖角固定使用旧紫色背景 `#E5DAFF`，标题文字 `#4C1D95`，不再随状态变色；两侧正文值和缺失占位均为普通文字，不铺状态背景、不画低置信度红框。单值浮层使用原有自适应宽度和 12.5px 正文，不套用对照值框布局。原有低分徽标 `#FFDADD`／文字 `#9B1C1C` 和真实分数保留；PDF 来源与 Fields 的状态色及红框不受影响。

Legend 同步说明五态背景和独立低置信度描边，不再合并漏提取与其他浅红错误，也不把参考颜色或高置信度误称为匹配成功。

上述共享配色应用于 PDF Fields，匹配／错误／漏提取三态仅在字段对照上下文启用；不借修改共享 helper 改变 Paragraphs、Figures、Signatures 等无关视图。

切换 tab、筛选或更改阈值不能重载 Source、重置 PDF 页码／缩放／旋转，或重放旧的定位请求。更换输入时清除旧比较与旧来源请求。

## 5. Viewer、Demo 与宿主边界

- 比较与展示在 Viewer 中完成；本轮 Go `label show` 自动读取完整 PDF 文件名加 `.labels.json`／`.result.json`，兼容 `label view`。
- Demo 从项目资源加载 PDF、Receipt PNG、Large PDF、PDF + Labels 四个入口，不依赖 Downloads、用户机器路径或新增服务接口。
- 既有三个真实分析结果只改名为 `.pdf.result.json`／`.png.result.json`，不重写 JSON，不调用 Analyze。
- 只有标签时不伪造分析结果；非法或不支持的已提供结果在页面明确告警，继续标签参考模式，不显示“全部匹配”。
- 保留公开 `source`、`labels`、`result` 输入及页面安全校验。Go 宿主提供可选 `warnings`；结果读取／校验失败时终端和页面明确告警，不重新分析。标签上限保持 500,000 bytes，新增可选结果读取上限 64 MiB。
- 标签查看／对照操作不能自动启用 analyzer 字段排序写回。
