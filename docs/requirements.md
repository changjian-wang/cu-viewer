# 需求

本文定义当前 cu-cli Viewer 的交付范围，以用户最新明确确认的需求为准。使用说明见 [README](../README.md)，进度见[开发计划](dev-plan.md)。

2026-10-27 已进入原型对齐的 React UI 落地规划。视觉及交互细节以 [UI 改造需求](ui-redesign/requirements.md)为准，实施阶段与验收统一维护在[开发计划的 UI 迁移章节](dev-plan.md#ui-redesign-react-migration)；计划更新不代表新 UI 已实现。未冲突的解析、格式支持、资源交付与只读职责继续有效。

## 目标与职责

提供 React/TypeScript 组件，让 cu-cli 在浏览器中并排展示原始 PDF/图片和 CU 分析结果，并在结果与真实来源间关联定位。

- 已确认下一版优先服务 CU 开发者、技术实施及技术测试人员，保持只读，不加入字段纠错、人工审核状态或修改保存。
- 本轮按已确认原型规划 UI 改造，包括 Fields 内的字段／值检索与同级展示排序；保持既有调用兼容，不迁入 toolkit、不发布版本，不新增跨文档批量浏览、全文检索或对比。
- Viewer 只负责渲染，不调用 Analyze、不依赖 CU SDK，不认证、不上传、不管理 analyzer、不轮询 LRO。
- Go、Python、C# 等 CLI 自行负责源文件和原始结果、Release 下载缓存、输入校验、只读本地服务、浏览器启动及生命周期；本仓库不再发行或维护 Python 宿主包/命令/API。
- 原始需求已约定 `cu analyze sample.pdf --view`：分析完成后将源文件及原始结果交给浏览器 Viewer。不带 `--view` 时不自动打开 Viewer。
- 后续已确认 `cu analyze sample.pdf --view --result sample.result.json`：只读取已有源文件和 JSON，跳过分析、登录和服务调用。无效或缺失的结果必须报错，不得回退到重新分析。
- 已确认首版每次查看一份本地 PDF/图片；现有批量和 URL 分析保持原样，不新增这些输入与 `--view` 的组合。
- 保持组件与 CLI 职责分离，Viewer 可以独立开发、运行演示和测试。
- 前端资源按下述统一 Release 契约获取，普通用户无需前端构建环境；CLI 自身代码的安装/更新由各自项目负责。

### 统一前端资源交付（2026-11-03 确认）

- Go、Python、后续 C# 等宿主统一从 CU Viewer Release 获取同一套静态资源，不在各自语言包/仓库中复制或内嵌前端副本。TypeScript 版 cu-cli 等组件宿主允许使用 npm package，保留其构建和消费者验证。
- 每个 Release 使用合法 SemVer 标签及 `viewer.zip`/`manifest.json` 配对资源。清单 schema 2，当前 `protocolVersion: 1`；宿主校验版本、协议、路径、资源规模和归档/逐文件 SHA-256 后本地托管，不需要 Node/npm/gh。
- 有效兼容缓存直接用，支持离线且不自动升级。Go 的 `--view` 最多每 24 小时检查一次兼容新版本（3 秒超时），仅在 stderr 提示当前版本、新版本及 `azd ai cu viewer update`，不下载新版归档、不切换活动缓存；已知新版本在后续启动中继续提示，手动更新后清除。检查失败明确警告并继续使用有效缓存，可写的检查记录也会限制失败重试频率。其他 CLI 提供各自显式更新入口，不宣称它们已有此通知机制。旧独立 Python `cu-viewer update` 已移除。损坏/不完整缓存明确报告并重新获取，更新失败保留先前活动版本。
- 第一次缺少资源时先准备再分析/认证，进度和错误写 stderr，不污染结果 stdout。没有兼容 Release、下载失败或缓存不可写时非零退出，不开始分析、不打开空白页，不静默忽略 `--view`。分析后查看失败保留完整结果，不重新分析。
- 下载请求仅用于公开静态资源，不上传文档、结果或 Azure 凭据。首个 [v0.1.0-preview.1](https://github.com/changjian-wang/cu-viewer/releases/tag/v0.1.0-preview.1) 已按用户授权发布，并备份后替换本机 CU 扩展，完成真实资源下载、一次分析和本地查看验证；资源基于已提交源码，隔离 UI 预览仍未合入。后续源码/资源发布和本机安装变更继续按各自授权范围执行。
- 本仓库只保留 React/TypeScript 前端、Bash Release 工具及 npm 组件分发。相邻 Go 扩展已本地验证此契约；原 Python 宿主及专属构建/测试已删除，Python/C# 等 CLI 的接入/迁移在各自仓库另行完成，不宣称本轮已实现。

### Go azd 扩展集成

- Go 扩展复用 `frontend/app` 的生产构建及语言无关的确定性 ZIP/清单，不再将构建产物保存到 Go 源码或使用 `go:embed`；运行时按统一 Release 契约下载缓存。
- 首版入口为 `azd ai cu analyze sample_invoice.pdf --analyzer prebuilt-invoice --view`，仅支持一份本地 PDF/当前支持的图片；不扩展批量、目录、URL，也不移植 Python 的离线 `--result` 入口。
- Go 宿主接收同一次分析的完整原始 JSON，不重复调用 CU，不依赖默认 Markdown 输出，也不改变现有控制台和保存文件的输出规则。不带 `--view` 时行为保持不变。
- Go 宿主负责只读本地服务、会话数据和指定源文件、默认浏览器启动及 `Ctrl+C` 清理。仅监听 `127.0.0.1` 的系统分配端口，不开放工作目录。运行时不需要 Node.js/Python。
- 2026-11-06 交接补充：原始文档和结果仍只读；当前 CU 宿主另外提供会话范围、同源校验下的字段顺序读写。实际自定义顺序写入 azd 用户配置的 `extension.installed` 中字面扩展键 `azure.ai.content-understanding` 的 `Viewer.fieldOrderByAnalyzer`，仅按完整 analyzerId 保存，不记录 endpoint、文件名或 API 版本；同 analyzerId 跨资源复用。旧 endpoint 前缀键迁移并保留顺序，冲突明确报错、不覆盖。打开文件不写默认值，重置只删当前覆盖；旧宿主未声明能力时保留浏览器模式。详细协议及兼容要求见 [azd Viewer 字段顺序](../README.md#azd-viewer-preferences)。

## 组件输入

| 输入 | 要求 |
| --- | --- |
| `source` | `File \| Blob \| ArrayBuffer \| string`，提供原始源文件或浏览器可访问的 URL。 |
| `result` | `unknown`，传入已解析的原始 CU JSON 对象；支持 Succeeded envelope 或 inner result，不要求调用方标准化或构造 SDK 模型。 |

不修改调用方输入，不把内部 CU/PDF.js 类型作为集成契约。下一版为已确认的 React 排序需求规划可选初始顺序、受控顺序与变化回调，不改变上述两个必需输入；具体契约按 UI 开发计划冻结，不预先开发其他通用定制 API。

## 源文件与导航

- 支持 `.pdf`、`.jpg`、`.jpeg`、`.jpe`、`.png`、`.bmp`、`.heif`、`.heic`，图片使用公共适配层。
- 提供缩放、平移、Fit page/width、旋转、上一页/下一页、跳页及当前/总页数；支持多页 PDF。
- BUG-010（新增截图问题）：选择 150% 等固定比例后，整页四边必须在实际滚动范围内，原生滚动条／滚轮能够访问四角，不能因锚点平移产生负坐标裁切。保留所选百分比、页码、Table 3 等关联字段范围、来源几何及手势锚点；旋转、先滚动再拖动和小比例切换后也成立，不以切回 Fit page 代替修复。
- BUG-008：常规缩放期间持续显示同一来源、同一页、同一旋转角度的已绘制预览，离屏新光栅完成后再替换，不能仅隐藏 Loading 文字却留下空白。首次加载、来源／页／旋转变化及真实错误仍明确显示实际状态，不沿用不匹配的旧画面；当前渲染和来源层的就绪、命中、焦点及锚点约束不变。
- Hover/选择结果关联真实来源；仅显式选择或定位才跨页，悬停不翻页、不滚动原文。缩放、旋转、平移及视口变化后仍对齐，无来源时不补造区域。
- 多来源字段选中范围包含本页全部真实片段，适用于普通值、嵌套值和数组单元格；右侧仍只选同一字段，不推断相邻字段。相邻同列多行可显示一个精确、无填充的装饰外框，但不合并真实多边形、扩大命中或把空白当来源；跨栏、分散或会圈入其他字段（含已隐藏的缺失字段）时保留原轮廓，整组和原生表格不强行合框。来源数量及当前定位序号与框数分离，浮层仍位于当前连续来源块下方，分散位置各自定位，不强行拉动视口；失效或不在本页的定位点不得借其他片段伪造成功浮层。
- 显式定位保持 zoom/rotation，仅在目标位于可见视口外时调整平移，已可见目标不移动。
- 选中／临时显示框只在装饰层使用精细抗锯齿，避免小数坐标和设备缩放造成各边粗细不一；原线宽、颜色、真实坐标、语义填充和点击命中不变。同一已选范围不重复叠描，预览内容与实际固定状态保持独立。
- Source/Result 保持双栏、最小宽度及独立滚动，支持 Chrome/Edge 中的键盘、可见焦点和 ARIA 信息。
- 无效文件、JSON、页码和来源明确提示；源文件失败不隐藏有效结果，替换/取消/卸载释放自有资源。

## 结果视图

从原始 JSON 识别 GA `2025-11-01` 与 Preview `2026-06-01-preview` 的适用非空数据，按以下顺序生成标签，无值隐藏，未知属性保留在完整 Result：

`Fields → Markdown → Paragraphs → Figures → Signatures → Info → Result`

Fields 仅在当前 content 返回结构化 fields 时显示；没有 fields（如 prebuilt-layout）时隐藏，即使有原生 tables。此时默认选择非空 Markdown；Markdown 不存在时回退到其他适用视图，不显示空标签。

Tab 栏按可用宽度自动收纳，超出部分通过右侧 `...` 下拉菜单选择，不使用横向滚动。选中的视图标签始终可见，保留方向键及 Home/End 切换；菜单支持上下键、Home/End、Enter/Space 和 Esc。移除 Code 标签。

| 视图 | 要求 |
| --- | --- |
| Fields | 显示名称、原值、已有置信度及来源；支持嵌套对象/数组、多来源区域、折叠和固定选择，区分缺失与 `0`、`false`、空字符串、`null`。折叠对象显示真实值摘要，长值单行省略但可查看／复制完整原值，名称旁不显示 `n selected`；数组数量只在 Value 保留 `N items`，不在名称旁重复 `[数量]`。不影响选中、业务行号及来源。源表格点击临时聚拢已有的可靠关联字段，不新增 Document Tables 分组、不自动重排；表格无提取字段时解释无对应项。 |
| Markdown | 安全展示标题、列表、表格、代码等常规格式；危险 HTML/URL 不能执行。 |
| Paragraphs | 按连续来源页集合分组的无卡片紧凑列表，保持 CU 顺序和全局序号，不跨组重排或合并段落；跨页／无来源明确标注。页标题独立展开／收起，默认全展开且不增加行高，不清除固定选择。44px 底栏提供名称／路径／正文搜索、匹配段落循环导航和批量页组展开／收起，不显示原说明。搜索临时展开匹配组、禁用折叠，清空后恢复手动状态；无匹配明确提示并禁用导航，原文选中被搜索隐藏时提示但不清空搜索。导航选中并聚焦段落；新的原文定位只打开目标组并定位一次，不抢焦点。保留 role、完整来源及自然换行正文，不单独截断或折叠、不持久化偏好。 |
| Figures/Signatures | 从已加载 source 的真实区域裁剪，显示已有 metadata 并定位，不推断签名状态或虚构图片。 |
| Info | 替代 Metadata；依次显示所有 `result.contents[*].metadata`（按 content 分组）、顶层 `usage`、`result.infos`、`result.warnings`。类似 Fields 的只读名称／值树形表，默认全部展开，可折叠但无 Copy 控件；保留空对象／数组、null、0、false、空字符串，无来源或 Confidence，不写配置。 |
| Result | 成熟交互 JSON 树支持合理规模的大结果，展示完整原始输入/envelope，包括 usage；根展开、嵌套折叠。 |

切换标签不重挂 Source，不重置页码、缩放、旋转、平移或固定项/区域索引；切换 content 时重算适用视图。

Info 不局限于选中的 content，也不受 Preview 版本限制；读取原始操作响应或 inner result 中实际存在的属性，缺失分组不补造，明确返回的空值仍展示。非法或超出既有 JSON 显示容量的数据明确报错，原始 Result 保留。

Info 用与 Fields 一致的 44px 底栏、右侧设置齿轮和弹层替代底部说明文字。设置仅含 `Collapse all groups`／`Expand all groups`，覆盖所有非空对象、数组及隐藏后代；没有可展开分组时两项均禁用，操作后不自动关闭。Esc 或关闭按钮恢复齿轮焦点，外部点击／焦点移出关闭但不抢焦点；换结果关闭设置并恢复默认展开。批量操作只影响 Info，不改 Fields、原始结果或配置。

Info 的 metadata 按 `metadata → contents[N] → 属性` 分层，单 content 也保留 `contents[0]`；仅显示实际返回的 metadata，保留原始零基序号及各 content 的内部路径，总组和各子组可独立折叠。正文与 Fields 共用 12.5px 常规字重及 20px 行高，顶层标题 600、嵌套组 500、数组计数 11px。infos、warnings 及其他嵌套数组项统一使用一基小写 `item N` 自动标签，不改变原字段名或值的大小写，仍保留零基原始路径；单项为 `1 item`。长名称单行省略但完整可访问，长值完整换行；空容器保持分组样式但不提供无效展开按钮。

Info 中数值映射型 `usage.tokens` 折叠后，在右侧值列显示模型名与计数的摘要。同模型名精确匹配的 `-input`／`-output` 成对计数合并为 `模型 (in 数值 / out 数值)`，不同模型按首次出现顺序分组，以分号分隔；未知或未配对的键保留原名与数值，不猜测其他计数类型。摘要固定单行、与普通行同高，不撑宽或增高；优先省略长模型名，若完整计数仍放不下则对摘要明确显示省略号。悬停或键盘聚焦可查看完整摘要，Esc 关闭提示；摘要可通过点击、Enter 或 Space 展开，焦点回到左侧展开按钮。展开后的原始值和顺序完整保留，其他分组及非计数结构的既有行为不变。

## 已确认的来源交互

- Legend 从齿轮设置独立到 Source 顶部文件信息与设置之间；面板宽度达到 1040px 时常驻五项简版图例，较窄时收为 Legend 按钮，完整五项说明按点击展开。断点按 Source 容器而非整个窗口判断，顶部工具栏保持原 57px 高度，Legend 本身不增加行高。齿轮保留阈值及三个总开关；宽版和完整 Legend 共用可点击、可键盘操作的五项 Source 分类显示状态，默认全开，关闭项空心斜线／弱化文字，但保留名称说明。Legend／设置互斥，支持合理的 Esc／关闭焦点恢复及外部／键盘移出关闭。
- BUG-003 已确认底部文档控制栏：来源视口下方以 44px 行高呈现居中页码和靠右的缩放／适应／旋转，保留原操作、输入校验和焦点恢复。BUG-005 确认旋转在所有支持宽度下直接显示，移除顶部 More 和独立布局重置菜单入口；拖动分栏和双击分隔条复位保留。2026-11-05 用户明确确认左下角只保留文件图标和文件名，移除此前 BUG-009 并入该处的所有状态／字段说明、计数、多来源切换按钮和分组来源页选择器，不迁移或新增替代控件。选择变化不增减行高；右侧字段定位、居中页码导航、原文来源点击、真实错误提示和非视觉手势帮助保持不变。底部 X 继续移除，保留已有 Esc／原文空白处点击及原清除逻辑。fit 使用实际可用空间，不修改原始文件或来源坐标。
- 分类开关只控制 Source 填色与装饰外沿，不筛选右侧 Fields、修改低置信度判定／提示、计数、原始数据或来源几何，也不移除来源命中、固定／预览轮廓。字段／表格总开关优先，对应禁用项显示原因；低置信强调关闭时两项 Low 禁用，原有正常色渲染归 Field／Table 类控制。N/A 继续表示“未返回置信度”，不同于真实 `0` 和“值未返回”，在任一字段／表格总开关开启时可控制。子项选择随现有偏好保存且总控关闭不重置；旧 v1 记录缺少分类字段默认全开，外层格式／键及必需公开输入不变，非法分类映射明确报错，不静默覆盖。
- 当前 Tab 决定适用来源框，不同 Tab 的框不混画；Fields／表格值按提取类型与自身置信度使用新 UI 语义色，不再继承根字段身份色。其余真实来源及表格整框保留；表格导航采用下面已确认的直接定位方式。
- 右侧字段 hover 显示原文附近的名称/Value/已有 Confidence，段落只显示 Content。其他来源框保留，预览不替换固定选择。
